Backup: Soundness by Logical Relations

The semantics delays $\cTDom{T}$ until $T$ resolves to an arrow, as the typing does.
delay $\Vint{\cTDom{T}}{s} = \Vint{T}{s.\sldom} \qquad \Vint{\cTRange{T}}{s} = \Vint{T}{s.\slran}$
resolve $\Vint{T_1 \to T_2}{s.\sldom} = \Vint{T_1}{s} \qquad\ \ \, \Vint{T_1 \to T_2}{s.\slran} = \Vint{T_2}{s}$
A ${\cpath\textsf{dom}}$ step flips polarity, as the domain of an arrow does.
$\LF{V}$: if the domain of $V$ has a value, every value of $V$ is a function. the witness property as a semantic invariant, required of every type variable's interpretation
Semantic type soundness and weak normalization, mechanized in Rocq. every F<: program stays typeable; the development also covers product projections and higher kinds

Backup: Why a Value Is a Witness

A subtyping derivation can end at $\cTDom{F}$ in only three ways.
introduction $A <: \cTDom{A \to B}$ the projected type is an arrow
congruence $\inferfrac{F <: S}{\cTDom{S} <: \cTDom{F}}$ move up to a supertype of $F$
bottom $\TBot <: \cTDom{F}$ no value has type $\TBot$
So $F <: A \to B$ for some arrow, and every $f : F$ is a function. F = Bot: Dom(Bot) ≡ Top is inhabited, but no f : Bot exists; the proof is mechanized

Backup: Why Call-by-Value

The argument is the witness, so it must be a value before the call reduces. 

  val etaErr = eta[Int](42)   //: Dom(Int) -> Range(Int)
  def loop(): Bot = loop()    // loop() : Bot <: Dom(Int)
  etaErr(loop())
call-by-valueloop() runs first and diverges; 42 is never applied
call-by-namethe body runs first: !!42(loop())!! is stuck
A term certifies the type only once it is a value. the calculus has no general recursion; DOT and Scala rest on the same principle

Backup: Intersection Types

Under an intersection of arrows, the two projections can come from different arrows.
$F := (\TInt \to \TInt) \wedge (\TBool \to \TBool) \qquad \TBool <: \cTDom{F} \qquad \cTRange{F} <: \TInt$
the identity inhabits F, yet the rule types f(true) at Int
A limitation: the argument witnesses the domain, not which arrow gives the result. so overloading as intersection is out of scope; TypeScript's utility types pick the last overload; set-theoretic types suggest a projection F ∘ S that keeps the correlation

Backup: Type Parameters and Type Members

Scala selects a type member through a term: f.Arg needs f in scope. 

  trait Fn { type Arg; type Res; def apply(x: Arg): Res }
  def eta(f: Fn)(x: f.Arg): f.Res = f.apply(x)           // ok
  def eta2[F <: Fn](f: F)(x: F#Arg): F#Res = f.apply(x)  // !!error!!
projection F#Arg on an abstract F was dropped as unsound (bad bounds, dotty issue 1050)
$\cTDom{F}$ projects a type, not a term: it is common to every function of type $F$.
A term is still needed, but only at the call: the argument. Dotty tried to encode type parameters as type members (Odersky et al., SCALA'16)

Backup: map with One Type Variable

Projections are ordinary types, so they nest: one type variable types $\textit{map}$.
$\textit{map} \;:\; \forall A, B.\ (A \to B) \to \TList{A} \to \TList{B}$
$\textit{map} \;:\; \forall F <: \TTop.\ F \to \TList{\cTDom{F}} \to \TList{\cTRange{F}}$
$\textit{map} \;:=\; \Lambda F.\ \lambda f.\ \lambda \ell.\ \Lambda R.\ \lambda c.\ \lambda n.\ \ell\,[R]\,(\lambda x : \cTDom{F}.\ \lambda a.\ c\,(\chl{f(x)})\,(a))\,(n)$
Only $\chl{f(x)}$ uses the proposed rule; every other call has an arrow type. Church-encoded lists, List A := ∀R. (A → R → R) → R → R; at F := A → B, callers see the classic map

Backup: Type Destructors and the Cast Back

Type destructors follow the same idea: η-equivalence recovers the components.
$X \;\equiv_\eta\; X.1 \times X.2 \qquad \text{for } X <: \TTop \times \TTop$
proposed by Hofmann and Pierce (I&C 2002), who give no destructors for arrows
TypeScript code wants the same for functions: it casts the wrapper back to T. 

  function logDecorator<T extends (...args: any) => any>(fn: T): T {
    return ((...args: Parameters<T>): ReturnType<T> => {
      [p[console.log("calling with", ...args);]]
      return fn(...args);
    }) [h[as T]];
  }
However, the cast is unsound once a function type describes more than its calls. 

  const taggedInc = Object.assign((x: number) => x + 1, { tag: "inc" });
  logDecorator(taggedInc)[h[.tag]].toUpperCase()   // type-checks, !!throws at run time!!

Backup: Image Types

The image $\cTImg{F}{X}$ types the results of an $F$ on arguments of type $X$.
$\inferfrac{f : F \qquad x : X \qquad X <: \cTDom{F}}{f(x) : \cTImg{F}{X}}$
The result type depends on the argument's type, so overloads keep their correlation. ongoing work: the image is a bounded type operator in $\mathsf{F}_{\omega<:}$, with $\TRange{F} := F \mathbin{@} \TDom{F}$
