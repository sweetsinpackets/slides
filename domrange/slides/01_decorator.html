Higher-Order Functions

A higher-order function can take a function as input, or return one as output.
For example, a decorator adds logging to any function. 

  function logDecorator([h[fn]]) {
    return (x) => {
      [p[console.log("calling with", x);]]
      return [h[fn(x)]];
    };
  }
  const add1 = (x) => x + 1;
  logDecorator(add1)(41)   // prints "calling with 41", returns 42
The decorator has a function parameter [h[fn]], and calls it as [h[fn(x)]].

Parametric Polymorphism

In TypeScript, we want one signature that works with all functions.
Parametric polymorphism gives it type parameters for the input and output of fn. generics in TypeScript; Λ and ∀ in System F 

  function logDecorator[h[<A, B>]](fn: [h[(x: A) => B]]): [h[(x: A) => B]] {
    return (x) => {
      [p[console.log("calling with", x);]]
      return fn(x);
    };
  }

Bounded Quantification

However, the signature is heavyweight: two type parameters per function. 

  function subscribe[h[<A, B, C, D>]](next: [h[(x: A) => B]], error: [h[(e: C) => D]]) { .. }
in languages with higher-rank polymorphism, users write type parameters explicitly
Can we use just one type variable per function?
Bounded quantification lets a type variable accept every subtype of a bound. bounded generics in TypeScript; ∀X <: T in System F<: 

  type Fn = (...args: never) => unknown;   // every function type extends it
  function logDecorator[h[<T extends Fn>]](fn: [h[T]]) { .. }

The Decorated Function Loses Its Type

However, the body observes fn only at the precision of the bound. 

  function logDecorator<T extends (...args: never) => unknown>(fn: T) {
    return (...args: [h[never]]): [h[unknown]] => {
      [p[console.log("calling with", args);]]
      return fn(...args);
    };
  }
So every decorated function must take never and return unknown. 

  const inc = logDecorator((x: number) => x + 1);   //: (...args: [h[never]]) => [h[unknown]]
  inc(41)   // !!error:!! [number] is not assignable to never

Early Exposure Loses Precision

The decorator's minimal form is an η-expansion.
$\textit{eta} \;:=\; \Lambda F <: \TBot \to \TTop.\ \lambda f : F.\ \lambda x : \chl{?}.\ f(x)$
never and unknown are $\TBot$ and $\TTop$
The only arrow type known for $f$ is $\TBot \to \TTop$, so $x$ must be typed as $\TBot$.
$\inferfrac{\inferfrac{f : F \qquad F <: \TBot \to \TTop}{f : \chl{\TBot \to \TTop}}\ \rulefmt{T-Sub} \qquad x : \chl{\TBot}}{f(x) : \chl{\TTop}}\ \rulefmt{T-App}$
To apply $f$, its arrow type must be exposed at the definition, which loses precision.
So this is a fundamental problem for bounded quantification.

Utility Types Recover Precision

To recover precision, TypeScript's utility types read the input and output off T. ReturnType appears in 88, Parameters in 82 of the 100 most-starred TypeScript repositories 

  function logDecorator<T extends (...args: [h[any]]) => [h[any]]>(fn: T) {
    return (...args: [h[Parameters<T>]]): [h[ReturnType<T>]] => {
      [p[console.log("calling with", ...args);]]
      return fn(...args);
    };
  }
The decorator must rely on [h[any]]: an unsafe type that bypasses every check on fn.
With a sound bound, never to unknown, its body is rejected. 

  // !!error:!! Parameters<T> is not assignable to never
  // !!error:!! unknown is not assignable to ReturnType<T>
